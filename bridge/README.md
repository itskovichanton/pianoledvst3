# PianoLedBridge

Подсветка клавиш пианино светодиодной лентой: Logic → VST3-плагин на JUCE → USB → ESP32-C6 → лента WS2812.

Одна клавиша = 3 светодиода, 144 светодиода на метр = 48 клавиш (MIDI 36–83, то есть C2–B5).

---

## Порядок запуска

### 1. Прошить плату

```bash
cd firmware
./flash.sh
```

Лента на GPIO4. Монитор не запускается намеренно — см. ниже.

### 2. Проверить железо БЕЗ Logic

Это главный шаг. Он отделяет «не работает железо» от «не работает плагин».

```bash
cd mac
./run_ledctl.sh ping     # нашлась ли лента, сколько в ней светодиодов
./run_ledctl.sh scale    # хроматическая гамма по всей ленте
./run_ledctl.sh chord    # до-мажорное трезвучие
./run_ledctl.sh off      # погасить
```

Если гамма бежит — железная половина исправна, дальше ищи в плагине.

### 3. Встроить в плагин

Добавь в проект плагина исходники:

```
shared/led_protocol.c
mac/src/frame_builder.cpp
mac/src/serial_port.cpp
mac/src/bridge.cpp
```

Пути к заголовкам: `mac/include`, `shared`.

В `PluginProcessor.h`:

```cpp
#include "LedBridgeGlue.h"

piano_led::PluginLedBridge ledBridge;
```

В `processBlock` — одна строка:

```cpp
ledBridge.processMidi (midiMessages);
```

В конструкторе `ledBridge.start();`, в деструкторе `ledBridge.stop();`.

### 4. Тесты

```bash
cd mac && ./run_tests.sh
```

208 проверок в четырёх наборах.

## Как это устроено

```
processBlock (realtime)  →  атомарная битовая маска 128 нот
                                    ↓
             juce::Timer 120 Гц  →  сборка кадра 432 байта
                                    ↓
                        /dev/cu.usbmodem* (USB CDC)
                                    ↓
       ESP32: декодер → защита по току → led_strip_refresh
```

### Почему аудио-поток трогает только биты

`processBlock` — realtime-поток. Опоздание в нём слышно как щелчок или дропаут в Logic. Поэтому оттуда нельзя выделять память, брать мьютексы, трогать файлы и писать в порт.

`processMidi()` не делает ничего из этого — только переставляет биты в `std::atomic<uint64_t>[2]`. Это проверяется тестом буквально: `test_mac_side` подменяет глобальный `operator new` и убеждается, что 176 000 MIDI-событий не вызвали ни одной аллокации. Там же есть тест самого детектора — иначе он мог бы быть сломан и всегда показывать ноль.

### Почему лимит тока в прошивке, а не на Mac

Питание от ноутбука, плата не готова отдавать больше 200 мА. Если бы лимит соблюдал хост, то любая ошибка в плагине упиралась бы в железо напрямую.

Прошивка физически рядом с лентой, поэтому решает она: `led_guard.c` считает ток каждого кадра и, если он выше 150 мА, пропорционально притушивает весь кадр. Что бы ни прислал Mac — превысить лимит невозможно.

Пропорционально, а не обрезкой ярких пикселей: картинка тогда тускнеет целиком и остаётся узнаваемой.

### Почему консоль в прошивке отключена

У C6 порт USB Serial/JTAG **один**, и по нему же идут кадры пикселей. Любой `ESP_LOG` вклинился бы в середину кадра. Поэтому в `sdkconfig.defaults` стоит `CONFIG_ESP_CONSOLE_NONE`, а диагностика уходит хосту отдельным типом кадра — `LED_FRAME_LOG`, который печатает `ledctl`.

Отсюда же и то, что `flash.sh` не запускает монитор: он показал бы нечитаемый бинарный поток и вдобавок занял порт.

### Почему кадр целиком, а не дельты

432 байта на 120 Гц — это 52 КБ/с, для USB CDC ничто. Дельты дали бы рассинхрон состояния при потере байта, а полный кадр самовосстанавливается за 8 мс.

Кадры уходят только при смене нот. Пока руки неподвижны, по проводу не идёт ничего — значит любая активность на линии это реально сыгранная нота, и отладка становится тривиальной.

### Почему лента гаснет сама

Закрыли Logic, выдернули провод, упал плагин — без watchdog лента осталась бы гореть до отключения питания. Прошивка гасит её после 2 секунд молчания хоста. Плагин, в свою очередь, раз в 500 мс шлёт кадр принудительно, чтобы выдержанный аккорд не потух.

## Раскладка

Никакого файла раскладки нет — это арифметика:

```
первый_светодиод = (midi_нота − 36) × 3
```

Настраивается через `StripLayout`: `ledCount`, `ledsPerKey`, `lowestNote`, `reversed` (если лента уложена справа налево).

## Протокол

```
0xAA 0x55 | тип | длина_lo длина_hi | payload | xor
```

Типы: `PIXELS` (RGB по светодиоду), `PING`/`PONG` (поиск устройства), `LOG` (диагностика с платы), `CLEAR` (погасить).

`shared/led_protocol.c` компилируется **обеими** сторонами провода — Mac и прошивкой. Тесты гоняют кодировщик против декодера, поэтому стороны не могут разойтись.

## Задержка

| Звено | Вклад |
|---|---|
| буфер Logic (128 сэмплов @ 48 кГц) | 2.7 мс |
| период таймера (120 Гц) | до 8.3 мс |
| USB CDC | < 1 мс |
| вывод WS2812 на 144 диода | 4.3 мс |
| **итого худший случай** | **≈ 15 мс** |

## Что проверено, а что нет

**Проверено тестами** (208 проверок, все зелёные): протокол и его ресинхронизация после мусора, отсутствие аллокаций в аудио-потоке, арифметика раскладки, защита по току на границах, транспорт через настоящий псевдотерминал с эмулятором прошивки на дальнем конце.

**Не проверено:** сборка прошивки — ESP-IDF в тестовой среде нет. Логика прошивки (`led_guard.c`, `led_protocol.c`) вынесена в файлы без зависимостей от IDF и протестирована нативно, но сам `main.c` с вызовами `led_strip_*` и `usb_serial_jtag_*` собирается только у тебя через `./flash.sh`.

Отдельная оговорка про `test_serial_pty`: настоящее выдёргивание USB псевдотерминалом не воспроизводится — на Linux запись в мастер после закрытия слейва молча проглатывается (проверено пробой), на macOS даёт EIO. Поэтому проверяется не обрыв как таковой, а что ошибка записи доходит до вызывающего.

## Яркость

Всегда 1%, настройки нет. Задана одной константой:

**`mac/include/piano_led/config.h`**

```cpp
inline constexpr Rgb kNoteColor{3, 0, 0};   // красный, 1% (3 из 255)
```

Вся лента целиком на этой яркости берёт около 34 мА при бюджете 150 мА. Плюс прошивка независимо считает ток каждого кадра и притушила бы его, если бы он вышел за лимит.

Если на железе лента окажется пятнистой или будет подмигивать — это известная особенность WS2812B на очень низких значениях PWM. Лечится увеличением тройки в этой строке (8–10 даёт около 100 мА на всю ленту).
